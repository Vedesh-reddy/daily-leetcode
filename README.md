# daily-leetcode

> **SIMULATED EDUCATIONAL GIT ACTIVITY DEMONSTRATION**
>
> The commit history of this repository was generated by a script. Every commit
> timestamp was set artificially with `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE`.
> The dates (1 Aug 2026 to 7 Oct 2026) do **not** reflect when the code was
> actually written or solved. Do not read this history, or any contribution graph
> built from it, as a record of real day-by-day activity.

## What this demonstrates

- How Git stores two separate timestamps per commit (author date and committer date)
- How those timestamps can be set to any value when a commit is created
- How automated, scripted commits look in `git log`
- How GitHub's contribution graph reads these dates

## Contents

`solutions/` holds 110 Java LeetCode solutions, one per commit. Solutions 01 to 83
come from the original daily-leetcode repository; 84 to 110 were added for this demo.

## How the history was produced

```bash
export GIT_AUTHOR_DATE="2026-08-03T21:14:00+05:30"
export GIT_COMMITTER_DATE="$GIT_AUTHOR_DATE"
git add solutions/NN.problem-name-difficulty.java
git commit -m "Solve Problem Name (#NN)"
```

## Inspecting it

```bash
git log --format='%h  %ad  %cd  %s' --date=iso
git cat-file -p HEAD          # raw author/committer lines with Unix epoch + offset
git log --date=short --format=%ad | sort | uniq -c   # commits per day
```

## How GitHub counts these commits

GitHub places a commit on the contribution graph using its **author date**, not the
push date. A commit only counts if its author email is linked to a GitHub account
and it lands on the repository's default branch (or `gh-pages`). Because Git lets
anyone set the author date freely, contribution graphs are not proof of when work
happened.
